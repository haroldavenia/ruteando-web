Resultado: `deleted`, `not_found` o `conflict` (el mismo `error` del 409: `CONFLICT`, `details.referencedBy`, `details.ids`). Un conflicto no corta el resto. |
| M2 | corregido | `PATCH /api/v1/packages/status` con `{ ids, status, reason }`. `reason` es opcional y vale para todos, con las reglas del PATCH de un paquete. Status desconocido o `reason` que no aplica: **422** y no se escribe ninguno. Por id: `updated` o `not_found`. Un audit `package.status.change` por paquete actualizado. El PATCH de uno no cambia. |
| M3 | corregido | `GET /api/v1/journeys/{id}/package-statuses`. No devuelve la jornada. Por cada parada con `packageId`: `routeIndex`, `sequence`, `stopType`, `packageId`, `status` y `statusReason` del paquete actual. Jornada de otro tenant: **404**. |
| M4 | corregido | `dateFrom` y `dateTo` (Instant UTC, inclusive) en `GET /api/v1/audit-logs`, `/audit-logs/me` y `/audit-logs/admin`. Si `dateFrom` es posterior a `dateTo`, **400**. |
| M5 | corregido | `GET /api/v1/packages?q=` se combina con `page`, `status` y `serviceType`. Coincidencia sin distinguir mayúsculas en `guideNumber`, `name` y `address`. El texto se escapa (un punto no es comodín) y no puede pasar de 80 caracteres. No usa índice `$text`. |
