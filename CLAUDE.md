# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Visión general

Ruteando es una aplicación web de planificación de rutas. La migración desde AngularJS terminó: el repositorio contiene un único frontend y un servidor mínimo. El código de la aplicación AngularJS anterior (`master/`, `externModules/`, `json/`, el backend de ejemplo de Satellizer) solo existe en el historial de git; el último commit que lo contiene es `19b1cb4`.

| Directorio | Qué es |
|---|---|
| `ng-ruteando/` | Frontend Angular 21.2 (standalone, scss, SSR con `server.ts`, zone.js conservado) con Angular Material 21.2 (tema M3): acceso, flota, lugares, paquetes, configuraciones, jornadas (con mapa de rutas, detalle de ruta y visitas) y zonas, sobre el HanoIT Gateway. Ver los changes de `openspec/`. |
| `server/` | Servidor Express mínimo: reenvía `/gateway/**` al HanoIT Gateway (`gateway-proxy.js`), publica la compilación de navegador de `ng-ruteando` y responde la página de la aplicación a las rutas del cliente. Pruebas en `server/test/`. |
| `openspec/` | Specs vigentes (`specs/`) y changes (`changes/`, con `archive/` para los terminados). |
| `scripts/` | `extract-gateway-fixtures.mjs`: regenera los fixtures sanitizados del gateway. |

## Comandos

### Frontend Angular (`ng-ruteando/`)
Requiere Node `^20.19 || ^22.12 || >=24` (`ng-ruteando/.nvmrc` = 22; usa `nvm use`); **el servidor** exige `^22.13 || >=24` (`node:sqlite`). **Gestor de paquetes: pnpm** (ver «Gestor de paquetes» más abajo): `pnpm install --frozen-lockfile` en la raíz instala todo, `pnpm start` (dev, puerto 4200), `pnpm run build`, `pnpm test` (Karma interactivo), `pnpm run test:ci` (una ejecución con Chrome sin interfaz) y `pnpm run serve:ssr:ng-ruteando` tras compilar (puerto 4000).

Entornos: `src/environments/environment.ts` (producción) y `environment.development.ts` (`ng serve`) definen `apiUrl` (`/gateway`), que se provee con el token `API_BASE_URL`. `ng serve` usa `ng-ruteando/proxy.conf.js`, que reenvía `/gateway` al gateway con `X-Api-Key` tomada de `GATEWAY_URL` y `GATEWAY_API_KEY` (entorno o `.env` de la raíz); sin ellas avisa y responde 503. Ver «Proxy del HanoIT Gateway» más abajo. **Esqueletos de carga**: `GATEWAY_DELAY_MS` (ms, tope 30000; vacío o 0 = apagado) retrasa cada petición en ese mismo proxy para ver los esqueletos; solo existe en `ng serve` (también con Docker, que lee el `.env` montado), el servidor de producción no lo lee, y hay que reiniciar `ng serve` al cambiarlo. El componente `shared/ui/skeleton.component.ts` (`app-skeleton`, variantes `stats`, `form`, `list`, `ring`, con `label` para el lector de pantalla) sustituye a la barra de progreso en detalle de jornada, detalle de ruta, Inicio, los siete formularios de edición (`RecordLoader` en `loading`) y el diálogo de asignar conductor; las tablas siguen con las filas de `DataTableComponent`, y las barras de envío (login, planificar, importar) se quedan como están.

### Gestor de paquetes (pnpm)
El repositorio usa **pnpm** (workspace de dos paquetes: la raíz, que es el servidor, y `ng-ruteando`), con **un solo `pnpm-lock.yaml`** en la raíz; ya no hay `package-lock.json` (están en `.gitignore` para que un `npm install` accidental no los cuele). La versión sale de `packageManager` en `package.json` (corepack, o el propio pnpm 10 la descarga si la local es otra; los contenedores y la CI la toman de ahí). Comandos: `pnpm install --frozen-lockfile` (como `npm ci`), `pnpm add <paquete>` en la carpeta del paquete (o `-w` en la raíz), `pnpm --filter ng-ruteando run <script>` desde la raíz o `pnpm run <script>` dentro de `ng-ruteando/`, `pnpm dlx` en lugar de `npx` (la CI mantiene `npx` solo para el CLI de OpenSpec, que no es una dependencia). Los argumentos van directos, sin `--`: `pnpm start --host 0.0.0.0 --port 4300`. pnpm es estricto: un paquete que el código importe pero no figure en su `package.json` no se resuelve (no hay «dependencias fantasma»); decláralo. pnpm 10 **no ejecuta los scripts de instalación** de las dependencias: `ignoredBuiltDependencies` de `pnpm-workspace.yaml` lista los cuatro que lo piden (esbuild, lmdb, @parcel/watcher, msgpackr-extract; traen su binario como paquete opcional y todo funciona sin ejecutarlos); si una dependencia nueva exige uno, `pnpm approve-builds`. La migración (de dos `package-lock.json` a este) se hizo con `pnpm import` por proyecto y fusionando, así que las versiones resueltas son las mismas, salvo las dependencias transitivas de `express` del servidor, que ahora comparten las del frontend (más nuevas, dentro del rango). Detalle y decisiones: `openspec/changes/migrate-to-pnpm/`.

### Lint y formato (ESLint + Prettier)
`pnpm lint` (ESLint 9, flat config en `eslint.config.js`: `typescript-eslint`, `angular-eslint` para TypeScript y plantillas con accesibilidad, `simple-import-sort` con Angular y rxjs primero, `import` y buenas prácticas como `no-var` o `no-eval`) y `pnpm format` (Prettier, `.prettierrc`: comillas simples, ancho **120**, `parser: angular` en `*.html`) comprueban sin modificar; `pnpm lint:fix` y `pnpm format:fix` arreglan. Las dos comprobaciones se ejecutan en la CI antes de las pruebas y deben quedar en **0 errores y 0 avisos**. ESLint cubre solo `ng-ruteando/` (el servidor y `scripts/` son JavaScript de Node y solo pasan por Prettier); Prettier ignora `*.md`, `openspec/`, `.claude/`, los fixtures y las capturas. Reglas que importan al escribir código: **un `eslint-disable` lleva siempre su motivo** (`// eslint-disable-next-line regla -- por qué`); un import sin usar es un aviso; en plantillas las interacciones deben ser enfocables. **No cambies `quoteProps` ni `endOfLine` de Prettier**: `scripts/i18n-check.mjs` lee las claves de los diccionarios con comillas (`'Cerrar': …`) y en Windows el disco tiene CRLF (`endOfLine: auto`). Prettier reparte los títulos de las plantillas en varias líneas: en las pruebas compara `textContent?.trim()`. El commit del formato masivo está en `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs`). Detalle y decisiones: `openspec/changes/add-lint-format/`.

### Integración continua
`.github/workflows/ci.yml` (trabajos `frontend` —lint, formato, idiomas, iconos, pruebas y compilación—, `server`, `specs`, `audit` y el resumen `ci`, que es la comprobación obligatoria de `main`) y `.github/dependabot.yml`. Las acciones van fijadas por SHA con su versión en un comentario (se resuelven con `gh api repos/<acción>/git/ref/tags/<versión>`), el CLI de OpenSpec está fijado en `OPENSPEC_VERSION` y pnpm lo instala `pnpm/action-setup` con la versión del campo `packageManager` (no se repite en el flujo). La auditoría de producción (`pnpm audit --prod --audit-level=high`, un solo comando para la raíz y `ng-ruteando/`) debe estar limpia; `jspdf` y `@faker-js/faker` se retiraron por no usarse. Los comandos para repetirlo en local están en `README.md`.

### Servidor (`server/` y raíz)
- `pnpm install --frozen-lockfile` y `pnpm start` en la raíz ejecutan `node server/server.js`; las dependencias del servidor (`express`, `morgan`, `colors`, `http-proxy-middleware`) están en el `package.json` de la raíz. No hay base de datos ni MongoDB.
- Puerto: `PORT` o 3000. `server.js` carga `.env`, registra el proxy `/gateway`, responde 404 en JSON a `/api/*` y `/auth/*` (no son rutas del cliente), publica `ng-ruteando/dist/ng-ruteando/browser` (se cambia con `WEB_DIST`) y responde `index.csr.html` a las rutas del cliente; los ficheros inexistentes devuelven 404. Hay que compilar antes con `pnpm run build:web` (sin compilación el servidor arranca, avisa en el log y responde 503 en las rutas del cliente). El estático y el comodín van siempre al final de `server.js`.
- `pnpm run test:server` ejecuta las pruebas del servidor (`server/test/*.test.js`, `node:test`).
- La app Angular consume el **HanoIT Gateway** a través del proxy `/gateway` (ver abajo).

### Proxy del HanoIT Gateway (`/gateway`)
El servidor reenvía `/gateway/**` a `<GATEWAY_URL>/api/v1/**` y añade la cabecera `X-Api-Key` desde el servidor (`server/gateway-proxy.js`); el navegador nunca ve la clave y no hay CORS. Se configura con variables de entorno: copia `.env.example` a `.env` (ignorado por git) y rellena `GATEWAY_URL` y `GATEWAY_API_KEY`; `GATEWAY_TIMEOUT_MS` (opcional, 30000 por defecto). `server.js` carga `.env` al arrancar y no pisa variables ya definidas en el entorno. Sin esas variables el servidor arranca, avisa en el log y responde 503 en `/gateway/**`; si el gateway cae responde 502 y si tarda demasiado 504. La clave es un secreto: no la copies a ficheros versionados, a `environment*.ts` ni al frontend. El proxy se registra antes de `body-parser` para reenviar el cuerpo en streaming (multipart), y las rutas `/api/*` y `/auth/*` del propio servidor no pasan por él. **Con el 2FA activo el proxy descarta toda variante de la ruta del login** (`//auth/login`, `/auth/%6cogin`…; `isLoginPath`): solo la ruta exacta pasa por `server/mfa`, y cualquier otra llegaría al gateway, que normaliza la ruta y entrega la sesión sin segundo factor (probado: `server/test/mfa-server.test.js`). Con `GATEWAY_MODE=mock` el simulado escucha solo en `127.0.0.1` (`MOCK_GATEWAY_HOST`; ejecutado suelto, como en Docker, escucha en todas). **`GATEWAY_MODE`** (`real` por defecto, o `mock`) elige el gateway tanto en `ng serve` (`proxy.conf.js`) como en el servidor de producción: con `mock` el proxy apunta a `scripts/mock-gateway.mjs` (puerto `MOCK_GATEWAY_PORT`, 4010), que se arranca dentro del mismo proceso (muere con él; si el puerto ya lo usa otro simulado, lo reutiliza), no se envía la clave real, el registro lo avisa con «MODO MOCK» y un valor distinto de `real`/`mock` deja `/gateway` en 503. Los usuarios del simulado entran con `demo1234` salvo que se defina `MOCK_GATEWAY_PASSWORD`: **obligatorio definirla si el servidor es accesible desde fuera**. La lógica vive en `server/gateway-mode.js` y es PROVISIONAL (los datos del simulado son ficticios y se pierden al reiniciar); se retira borrando ese fichero y sus dos usos cuando los servicios reales estén estables. Cambiar de modo exige editar el `.env` y reiniciar, y la sesión del navegador deja de valer (el token es de un gateway concreto). Docker de desarrollo sigue con sus variables `DOCKER_GATEWAY_*`.

### Segundo factor (OTP por correo, OTP por SMS y TOTP)
El servidor impone un segundo factor opcional (o exigido por la empresa) en el login; el gateway no lo ofrece, así que **no vive en el frontend** (se saltaría llamando directo a `/gateway/auth/login`). Módulo `server/mfa/` (`createMfa(env)`, `mount(app)`): intercepta `POST /gateway/auth/login`, valida la contraseña con el gateway, **retiene los tokens en memoria** (reto de 5 minutos, una sola instancia) y devuelve `{ mfaRequired, challengeId, methods }` en lugar de la sesión; `POST /gateway/mfa/login/verify` la entrega al acertar. Las rutas viven bajo `/gateway/mfa/**` (así el cliente reutiliza token, renovación y errores): `login/send|verify|complete` (sin sesión), `status`, `email|sms|totp/setup|confirm`, `session/send`, `methods/:método` (DELETE), `recovery-codes/regenerate`, `policy` y `users` (+ `users/:id/reset`, solo `tenant_admin` y `super_admin`). Se registra **antes** del proxy en `server.js` y, en `ng serve`, `proxy.conf.js` arranca el mismo módulo en `MFA_DEV_PORT` (4020) y le envía el login y `/gateway/mfa`. **Sin `MFA_SECRET_KEY` queda apagado** (el login pasa como siempre y `/gateway/mfa` responde 503): generar una con `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`; cambiarla invalida los secretos TOTP guardados.

- **Métodos**: correo (SMTP con `nodemailer`; código de 6 dígitos propio, no el OTP del gateway, que no condiciona el login y no tiene límite de intentos), SMS (`SMS_PROVIDER=twilio` usa Twilio Verify por REST, con `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` y `TWILIO_VERIFY_SERVICE_SID`; `dev` lo entrega como correo a Mailpit) y TOTP (RFC 6238 con `node:crypto`, secreto cifrado con AES-256-GCM; el QR lo dibuja `qrcode` en el navegador, cargado solo en `/profile` y en la activación obligatoria). Códigos de recuperación: 10, de un solo uso, solo huellas en el almacén. Límites: 5 intentos por reto (después 429), **10 códigos erróneos por persona en 15 minutos** (después no se abren retos nuevos ni se acepta ningún código: 429 `TOO_MANY_FAILURES`), 3 envíos por persona y método cada 10 minutos y un código de correo o SMS de desarrollo muere tras 5 fallos. **El reto de activación obligatoria (`X-MFA-Challenge`) solo vale para `status` y las altas y confirmaciones de método**: el resto de rutas de `/gateway/mfa` exige una sesión de verdad (403). **Un método ya verificado no se pisa con una activación nueva** (409): se desactiva antes, con un código.
- **Almacén** `node:sqlite` (`MFA_DB_PATH`, por defecto `data/mfa.sqlite`, ignorado por git): política por empresa, factores, códigos de recuperación y eventos. Exige Node `^22.13 || >=24` en el servidor y **un volumen persistente en producción**. Los usuarios del gateway simulado cambian de id en cada arranque: tras reiniciarlo hay que volver a activar los métodos.
- **Pantallas**: segundo paso en el acceso (`features/access/login/mfa-*-step`), `/profile` (cualquier rol: activar y desactivar métodos con un código, códigos de recuperación) y `/security` (solo administradores: métodos permitidos, obligatoriedad por todos o por rol y restablecer el 2FA de una persona). Los componentes comunes están en `shared/mfa/`. **Elección del método al iniciar sesión**: con más de un método activo (correo, SMS, aplicación) el segundo paso muestra primero un selector y no envía ni pide nada hasta que la persona elige (el código de recuperación va como enlace aparte; «Elegir otro método» vuelve al selector); con un solo método va directo al código. **Aviso de activación** (`shared/mfa/mfa-reminder.component.ts`, en el shell): si no hay ningún método activo y la empresa permite y el servidor ofrece alguno, una franja ámbar bajo la barra invita a activarlo en `/profile` («Más tarde» la oculta hasta el próximo inicio de sesión; no sale en `/profile` ni con el módulo apagado); si la empresa lo exige ya lo pide el paso de activación obligatoria. **Correos** (`server/mfa/email-templates.js`, HTML con tablas y estilos en línea, degradado de la marca, emblema adjunto como `cid` —`email-logo.png`— y modo oscuro): `codeEmail` y `smsDevEmail` devuelven también `text` (las pruebas leen ese campo); todo valor variable se escapa. Los textos que escribe el servidor (correos, SMS) están en español: no se traducen.
- **Probar en local**: `docker compose up` incluye **Mailpit** (bandeja en http://localhost:8025, SMTP en 1025) y una `MFA_SECRET_KEY` de desarrollo; con `SMS_PROVIDER=dev` los SMS también llegan a Mailpit. Docker toma `SMS_PROVIDER` (por defecto `dev`) y `TWILIO_*` del `.env`; el paso a paso de Twilio y la lista de variables para desarrollo y producción están en `README.md` («Segundo factor»). Sin Docker: define `MFA_SECRET_KEY`, `SMTP_HOST=127.0.0.1` y `SMS_PROVIDER=dev` con `docker compose up mailpit`. Pendiente: verificar con el gateway real que `GET /auth/me`, `GET /users/:id` y el canal SMS se comportan como el simulado. Detalle y decisiones: `openspec/changes/add-mfa/`.

### Inicio de sesión único (SSO)
Módulo `server/sso/` (`createSso(env, { mfa })`, `mount(app)`; mismo patrón que `server/mfa/`, registrado **antes** del proxy en `server.js` y en `proxy.conf.js`). Google y Apple (OIDC), GitHub (OAuth 2.0) y el proveedor OIDC de cada empresa; **apagado sin `SSO_ENABLED_PROVIDERS`, `SSO_REDIRECT_BASE_URL` o `MFA_SECRET_KEY`** (`/gateway/sso/providers` responde `[]`, lo demás 503). Flujo: `GET /gateway/sso/:proveedor/start` (PKCE S256, `state`, `nonce`, cookie `HttpOnly` que liga el regreso al navegador) → proveedor → `GET|POST .../callback` (valida `id_token` con `jwt.js`/`oidc.js`, exige correo verificado) → **`POST /auth/sso/exchange` del gateway** (contrato en `openspec/changes/add-sso/design.md`; solo existe en el simulado, **hay que pedirlo al gateway real**; nunca crea cuentas) → ticket de un solo uso en `/access/sso#ticket=…` → `POST /gateway/sso/complete`, que responde lo mismo que el login (`mfa.afterLogin`: **el SSO no sustituye al segundo factor**). Una identidad `(proveedor, sub)` ya enlazada no pasa a otra persona (`IDENTITY_MISMATCH`). Gestión con sesión: `identities` (+ `DELETE`), `policy` (permitido por empresa, por defecto sí) y `enterprise` (un proveedor por empresa; secreto cifrado que nunca vuelve; dominios únicos; el correo debe estar en los dominios y la persona ser de esa empresa; emisor `https` público y llamadas salientes solo a IP públicas con `safe-fetch.js`, contra SSRF). Almacén aparte `node:sqlite` (`SSO_DB_PATH`). Cliente: `features/access/sso/` (botones y regreso), `shared/sso/sso-accounts.component.ts` (Perfil), `features/security/sso-settings.component.ts`. Probar sin cuentas reales: `node scripts/mock-oidc-provider.cjs` con `SSO_ALLOW_INSECURE=true` y `SSO_GOOGLE_ISSUER` (README, «Inicio de sesión único»). Sin verificar: Google, GitHub, Apple y un proveedor de empresa reales, y el intercambio con el gateway real.

### Cabeceras de seguridad
`server/security-headers.js` añade a todas las respuestas (antes del proxy y del estático) `nosniff`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`, `COOP`, HSTS solo con `X-Forwarded-Proto: https` y una CSP (`script-src 'self'`; solo Google Fonts y las teselas de OpenStreetMap como orígenes externos). `CSP_MODE` (`report-only` por defecto, `enforce`, `off`) y `CSP_IMG_SRC` (otro proveedor de teselas) la configuran. La compilación de producción desactiva `optimization.styles.inlineCritical` (`angular.json`): la carga diferida de los estilos críticos añade un `onload` que la CSP bloquea y rompe los estilos; no lo reactives. Verificado en navegador con `enforce`: sin violaciones. Tras añadir recursos externos o scripts en línea, comprueba con `report-only` antes de usar `enforce`.

### Docker de desarrollo
`compose.yaml` + `Dockerfile.dev` (Node 22; no es la imagen de producción): `docker compose up` levanta `mock-gateway` (:4010), `mailpit` (bandeja en :8025, SMTP en :1025; ver «Segundo factor») y `ng serve` (:4200, `--host 0.0.0.0 --poll 2000`) con el código montado y los `node_modules` en volúmenes con nombre; el servicio `deps` hace `pnpm install --frozen-lockfile` solo si cambió el hash del `pnpm-lock.yaml`. Perfiles: `prod-like` (compilación + Express en :3000) y `test` (Karma con Chromium). El gateway por defecto es el simulado; se cambia con `DOCKER_GATEWAY_URL` y `DOCKER_GATEWAY_API_KEY` (no con `GATEWAY_*`, porque compose lee el `.env` y apuntaría al gateway real por accidente). Sin scripts de shell versionados (con CRLF de Windows fallarían en el contenedor): los comandos van en el compose. Detalle: `openspec/changes/add-dev-docker/`.

### PWA (instalable)
`@angular/service-worker` solo en la compilación de producción (`serviceWorker` en `angular.json`; `provideServiceWorker` con `!isDevMode()`): `ng serve` no lo tiene, se prueba con `pnpm run build:web` y `pnpm start`. `ngsw-config.json` declara `index: /index.csr.html` (el servidor publica esa página, no SSR) y **no cachea `/gateway`, `/api` ni `/auth`** (datos y sesión siempre por red); cachea la carcasa, las fuentes de Google y las teselas de OpenStreetMap (300, 7 días). `src/manifest.webmanifest` e iconos en `src/assets/icons/` (regenerar con `node scripts/generate-pwa-icons.mjs`, usa Chrome). El servidor sirve `ngsw-worker.js`, `ngsw.json` y el manifiesto con `Cache-Control: no-cache` (si no, el navegador nunca ve versiones nuevas), los ficheros con hash (`main-XXXXXXXX.js`, `styles-…css`, `chunk-…js`) como `immutable` un año, y la CSP lleva `worker-src` y `manifest-src`. `UpdateNotifier` (en `AppComponent`) avisa «Hay una versión nueva» con «Recargar»; `InstallService` (solo en el shell) ofrece «Instalar aplicación» en el menú de usuario (`beforeinstallprompt` lo captura `assets/install-init.js` desde el primer momento, y no entra en el bundle inicial, que está al límite de 500 kB) y en iOS una pista de «Compartir → Añadir a pantalla de inicio». `ThemeService` mantiene `theme-color` según el esquema. Los specs que crean `AppComponent` necesitan `provideServiceWorker('ngsw-worker.js', { enabled: false })`. **No pases los `chunk-*.js` a `lazy` en `ngsw-config.json`** para ahorrar los ~1,8 MB de la instalación: se probó y sin conexión la pantalla queda en blanco, porque los trozos de la pantalla de acceso nunca se guardan si la persona entró con sesión. Verificado en Chrome (CSP `enforce`): sin conexión, ciclo de actualización, teselas y que el menú ofrece instalar. Sin verificar aún: el cuadro real de instalación, Android/iOS y el proxy de producción (`openspec/changes/add-pwa-install/tasks.md`).

## Arquitectura / puntos a tener en cuenta

- Autenticación: la sesión es del gateway (`/auth/*` por `/gateway`); el servidor propio no autentica. `AuthService` restaura la sesión al arrancar y la renueva antes de que caduque, el interceptor de renovación reintenta en 401 con una sola petición compartida, y `TokenStorageService` guarda el access token en memoria y el refresh token en `localStorage` (`hanoitToken`, `hanoitTokenExpiresDate`, las mismas claves que usaba la app AngularJS); la caducidad se calcula con `Date.now() + expires_in * 1000` y el servicio es seguro en SSR.
- Consumo del gateway (`ng-ruteando/src/app/core/`): `api/` (interceptores, errores en español personalizables, paginación, servicios `data/*.api.ts`, modelos), `auth/` (sesión, guards, `TokenStorageService` seguro en SSR) y `geo/` (`LatLng`, polilíneas de precisión 5). Las coordenadas del gateway son `[lon, lat]`; en el dominio se usa `LatLng`. El campo `geoJson` de las rutas es una polilínea codificada, no GeoJSON. La subida de CSV y la geocodificación no tienen contrato documentado todavía. **Las rutas están en inglés** (`/access`, `/fleet/vehicles`, `/journeys/:id/routes/:routeIndex`, `/legal/privacy`…); `legacy-redirects.ts` reenvía las direcciones antiguas en español a las nuevas (con consulta y fragmento), para que enlaces y correos ya enviados sigan valiendo. Pantallas de acceso en `ng-ruteando/src/app/features/access/` (`/access`, `/access/register`, `/access/recover`, `/access/verify-email?token=`, `/access/reset?token=`): layout propio sin shell; el área privada (`''`, con el shell diferido) exige sesión y `/` ya no es pública; el destino tras el login pasa siempre por `safeReturnUrl`. `POST /auth/logout` lleva `{ refreshToken }`. Flota en `ng-ruteando/src/app/features/fleet/` (`/fleet/types`, `/fleet/vehicles`, `/fleet/drivers`, solo `tenant_admin` y `super_admin`) sobre el patrón de listado, borrado y envío de `shared/data/`. - **Idiomas (inglés por defecto, español y portugués)**, en `ng-ruteando/src/app/core/i18n/`. El **texto fuente de la aplicación es el español y es la clave de traducción**: los textos se escriben en español en el código y los diccionarios `dictionaries/en.ts` y `pt.ts` (cargados cada uno en su propio trozo, solo el del idioma activo) los traducen; el español no necesita diccionario (`t()` devuelve la clave). En TypeScript se usa `t('Texto')` y en plantillas `{{ 'Texto' | t }}` (`TranslatePipe`); con partes variables, marcadores `{0}`, `{1}`: `t('{0} de {1}', [a, b])`. **No armes frases por trozos** (`'Ver ' + x + ' en el mapa'`, plurales con `'evento'`/`'eventos'`): escribe frases completas y una clave por forma (`t('1 evento')`, `t('{0} eventos', [n])`), porque el orden y la concordancia cambian entre idiomas. Un texto español con **dos sentidos** se separa con contexto: `'Inicio||hora'` se ve «Inicio» en español y se traduce aparte de `'Inicio'` (menú). Atributos de Material con entrada propia (`mat-checkbox`, `mat-select`…) van con `[aria-label]`, no `[attr.aria-label]`. El idioma se decide **una vez al cargar la página** (`localStorage` `ruteando-lang`, o el inglés) y cambiarlo guarda y recarga (con una animación breve, `LanguageService`): por eso los dos diccionarios se importan de forma **estática** en `i18n.ts`: existen antes de que se evalúe cualquier módulo (así `t()` vale en constantes de módulo) y el navegador ve todo el grafo de módulos desde el HTML (cargar el diccionario o la app de forma diferida creaba una cadena de 5 niveles de peticiones y empeoraba el arranque). Cuestan ~100 kB sin comprimir en el bundle inicial (~35 kB comprimidos): el aviso de presupuesto está en 650 kB. Fechas y números usan `locale()` en `Intl`, no `'es'`. Las pruebas fijan el español (`src/testing/test-setup.ts` y `language.setup.spec.ts`) y comprueban los textos fuente; el inglés de lo que se evalúa al importar solo se ve en el navegador. `node scripts/i18n-check.mjs` (en la CI) exige que cada texto tenga traducción al inglés y al portugués, con los mismos marcadores y sin sobrantes, y `--spanish` lista textos en español que no pasan por `t()` (no ve palabras sueltas pasadas como argumento: barre las pantallas en el navegador, p. ej. con iframes). Selector de idioma: `shared/ui/language-toggle.component.ts` (`segmented` en el acceso, `menu` en la barra).
